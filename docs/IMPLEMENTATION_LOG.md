# Implementation log

Chronological summary of what was built and the problems found along the way. Details of fixes are in the CHANGELOG.

## Phase 0 — planning
Requirements analysed; missing requirements identified (document splitting, classification, spreadsheet schema mapping, user model, retention, tolerances,
embedding provider); architecture and roadmap approved. Owner's answers: Windows + Docker + 16 GB, free-tier LLM, English only, no sample documents, small team, invoices only
(receipts for verification), portfolio project.

## Phase 1.1 — tooling (verified in the owner's folder)
Repo skeleton, Ruff, mypy strict, pytest, pre-commit (hooks resolved from GitHub: pre-commit-hooks v6.0.0, ruff-pre-commit v0.17.6).

## Full build (all modules)
Built bottom-up and tested at each layer in a Linux sandbox with a **real PostgreSQL 16 + pgvector** (via `pgserver`), Tesseract 5.3, and later a real Redis 7.

1. **Core & database** — settings, structured logging, scrypt/JWT, rate limiter; 14 tables; Alembic migration autogenerated against real Postgres, then FTS index and `vector` extension added by hand; `alembic check` proves models == migration.
2. **Domain logic** — money/date parsing and the validation rules and matching, as pure functions.
3. **Processors** — magic-byte detection, integrity checks, PDF words/lines, OCR (preprocess → Tesseract → boxes), spreadsheets, page classification and splitting.
4. **AI layer** — extractor interface, heuristic and Gemini extractors, grounding, confidence, embeddings.
5. **Services & tasks** — pipeline stages with atomic claims, extraction, validation, corrections, comparison, search, stats; Celery tasks with failure recording.
6. **API** — 30 operations, middleware, error envelope.
7. **Tests** — written per layer; the first end-to-end run exposed most of the bugs listed below.
8. **Real-stack test** — separate Redis, worker and API processes; SIGKILL of the worker found the "lost message" weakness → reaper added.
9. **Measurements** — 1,000-page performance test, labeled evaluation, frontend/backend contract check.
10. **Frontend** — Next.js app; strict type-check; production build; routes/CORS/contract verified against the live stack.

## Bugs and design problems found by testing (all fixed)
| Found by | Problem | Fix |
|---|---|---|
| pipeline test | A bundle with one failed page could never recover that page's invoice on retry (old split reused) | split reconciliation on resume; test `test_page_failure_then_reprocess_failed_recovers` |
| unit test | CSV in cp1252 decoded as UTF-16 → garbage | UTF-16 only with BOM |
| OCR experiment | After deskew, line items vanished (text rebuilt from un-rotated coordinates) | build text from straightened coordinates, map only boxes back |
| unit test | Grounding rejected `Tax (10%) $2.55` (parsed 102.55) | amount = last number, percentages ignored |
| evaluation | All spreadsheet invoices flagged for review ("no line items") | layout-aware rule |
| pipeline test | Damaged PDF silently "completed" | repaired ⇒ always review |
| API test | PDF vs summary spreadsheet reported a discrepancy for missing line items | `not_comparable` verdict |
| perf test | Line items lost for unusual currency glyphs | glyph-tolerant number pattern |
| real-stack test | Killed worker leaves messages invisible for the visibility timeout | stalled-document reaper (Celery beat) |
| real-stack test | Dashboard SQL error | corrected join; test added |
| security test | Unknown routes bypassed the error envelope | handler registered for Starlette's HTTPException |
