# Next steps (in priority order)

## 1. Run it for real (first thing — ~30 minutes)
1. `copy .env.example .env`, set `JWT_SECRET`, passwords. `docker compose up --build`. **The Dockerfiles and Compose file were written but never executed** — expect small fixes (paths, health checks, permissions on the storage volume).
2. Open <http://localhost:3000>, sign in, upload files from `backend/` generated by `python -c "from app.devtools import synthetic ..."` or your own, and click through every page. **The UI has never been run in a browser.**
3. Run `.\scripts\test.ps1` (Windows) to confirm the test-suite passes on your machine against the Docker test database.
4. Create a GitHub repository, push, and confirm the CI workflow passes (it also builds the compose images).

## 2. Replace synthetic data with real data (most valuable work)
- Collect 100–300 real (or anonymised) invoices/receipts, label them (a spreadsheet of the 8 fields + line items is enough), and extend `scripts/evaluate.py` to read them. Until then the accuracy numbers only describe synthetic documents.
- Try the Gemini extractor (`LLM_PROVIDER=gemini`) on that set and compare cost, latency and accuracy with the heuristic baseline. It has never run against the real API.
- Tune the review threshold (`REVIEW_CONFIDENCE_THRESHOLD`) using the real review-recall vs. extra-work trade-off.

## 3. Quality improvements
- Browser tests (Playwright) for upload → review → correct → approve → compare.
- Real semantic search: `pip install ".[semantic]"`, `EMBEDDER=sentence-transformers`, then re-index (re-run analysis/reprocess) and build a small relevance-judged query set.
- PaddleOCR (or others) behind `OCREngine` and compare on the real set; add Bengali/other languages (`tesseract-ocr-ben`, `OCR_LANG=eng+ben`) if needed.
- LLM-assisted page classification/splitting for pages the rules are unsure about; LLM-assisted spreadsheet column mapping for unusual headers.
- Add/delete line items in the UI; carry line-item corrections across re-extraction.

## 4. Production hardening (see SECURITY.md)
HTTPS reverse proxy; httpOnly-cookie sessions; user-management UI + password change/reset; per-task sandboxing and no-egress workers; antivirus scanning; encryption at rest; S3/MinIO storage implementation;
dependency scanning; backup/restore runbook; metrics (Prometheus) and alerting on the failed/stalled counts.
